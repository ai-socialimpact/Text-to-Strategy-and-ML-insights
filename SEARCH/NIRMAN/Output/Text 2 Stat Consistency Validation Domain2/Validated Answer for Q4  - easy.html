4 4. Answer Contextualized by Schema & Domain Model
How the Project Schema Explains & Validates This Answer:

The question asks who took part in the NIRMAN Batch 14 Point-1 workshop (Workshop_Level 0.1), how many completed both the Pre and Post psychometric surveys, who they are by Gender and Medical vs Non-medical stream, and how many dropped out. NIRMAN is SEARCH's youth social-leadership program. Objective facts about a person (gender, stream, batch) sit in prod_nirman_demographics, which has one row per Participant_Id. Subjective Pre/Post psychometrics sit in prod_nirman_questionnaire, which has one row per (Participant_Id, Workshop_Level, Workshop_Phase). The consensus result is 148 unique participants in the questionnaire for Batch 14 Point 1. This equals the Batch 14 demographics roster of 148. All 148 have a Pre row and a Post row, which gives 296 filtered rows (148 × 2). Pre-only is 0, Post-only is 0 and the dropout rate is 0.00%. The join to demographics is lossless (effective N = 148, 0 not found). The cohort is 81 FEMALE (54.73%) and 67 MALE (45.27%), and 87 Medical (58.78%) vs 61 Non-medical (41.22%). The Gender × Medical cross-tab is F-Med 52, F-NonMed 29, M-Med 35, M-NonMed 32. These are descriptive, single-arm observational counts, with no causal claim about the workshop. Batch 14 falls inside the questionnaire's 7–17 coverage window and the demographics 1–17 window, so no structural coverage gap could cause a mismatch here. The perfect overlap is a feature of this batch, not of the whole dataset. The schema warns that not every participant appears in both tables.

Schema Entity / Table Role in Answer Relevance & Meaning
prod_nirman_questionnaire Defines the group (Batch 14, Point 1) and the survey-completion sets. Its grain is (Participant_Id, Workshop_Level, Workshop_Phase), so each participant can have up to two rows (Pre, Post) at Level 0.1. Therefore row counts (296) and participant counts (148) differ, and the question correctly asks for unique participants. Workshop_Level is numeric (0.1/0.2/0.3), hence the parseFloat comparison. Participant_Name is masked PII and is not used. Relevant Columns: Participant_Id, Workshop_Batch_Number, Workshop_Level, Workshop_Phase, Workshop_Name
prod_nirman_demographics Supplies the Batch 14 roster, a participant-grain registry with a unique Participant_Id, used for the roster-vs-survey reconciliation. It also supplies Gender and Educational_Stream_Category for the breakdowns. All of these are 'usable' zero-missing columns, so no nulls distort the percentages. 'Medical' in Educational_Stream_Category excludes Pharmacy, which sits in 'Arts/Commerce/Science/Pharmacy'. Relevant Columns: Participant_Id, Workshop_Batch_Number, Gender, Educational_Stream_Category
Join: demographics (1) → questionnaire (many) on Participant_Id The key is a numeric-looking STRING identifier (1001–17176) that must be cast to string in both tables. The join is one-to-many. The runs de-duplicated to one record per participant (the BOTH set) before the inner join. This prevents row inflation and gives an effective N equal to the number of unique participants. Not every participant appears in both tables in general, so effective N is always reported after the merge. Here nothing was lost. Relevant Columns: Participant_Id
Derived concepts (Pre/Post pairing and dropout) PRE_SET, POST_SET and BOTH implement the schema's pre_post_pairing recipe (Workshop_Phase 'Pre'/'Post' within Workshop_Level 0.1). Pre-only is treated as dropout, and Post-only is treated as a data-quality anomaly rather than a dropout. Gender × Medical is a participant-level descriptive cross-tab. Relevant Columns: Workshop_Phase, Workshop_Level, Participant_Id, Gender, Educational_Stream_Category
Domain Business Insights from Schema:
  • Report Batch 14 Point-1 as 148 matched Pre/Post participants (Pre = Post = Both = 148, dropout 0.00%) with the effective N stated, and always label counts as participants rather than rows.
  • Because the Pre/Post pairs are complete and fully matched to demographics, Batch 14 is a clean base for paired Pre vs Post analyses (theme deltas, Career_Plan_Social_Action_Engagement switch to full-time). Use the schema's pre_post_pairing recipe with reverse-coding and zero→NaN cleaning applied first.
  • State the Medical definition explicitly in every report: Educational_Stream_Category == 'Medical' excludes Pharmacy. If stakeholders want Pharmacy shown separately, use the partially usable Educational_Stream column and report the effective N after dropping nulls.
  • Treat 0% dropout as a completion statistic for Point 1 only. Confirm with the program team how Pre/Post surveys were administered and whether the dataset was filtered to completers before using it as a retention benchmark. For retention, use Workshops_Attended_Count and the Point_2/Point_3 invited/attended flags, noting that these are invitation-gated.
  • Repeat the roster-vs-survey reconciliation for the other batches (7–17) before generalising. Batches 1–6 have no questionnaire data, and other batches may show roster members without surveys, Pre-only dropouts or Post-only anomalies.
  • Keep the Gender × stream cross-tab descriptive. If a test of association is needed, use a chi-square or Fisher test and report effect size and N, and do not interpret the result as a workshop effect.
  • Keep Participant_Name out of all outputs, and keep Participant_Id cast to string in every load step of the JavaScript pipeline.
