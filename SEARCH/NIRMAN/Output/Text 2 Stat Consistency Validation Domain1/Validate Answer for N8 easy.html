4 4. Answer Contextualized by Schema & Domain Model
How the Project Schema Explains & Validates This Answer:

The question is a cohort profile of NIRMAN Batch 14, the youth social-leadership programme run by SEARCH. It uses only the objective-facts table, prod_nirman_demographics (one row per Participant_Id, 2,890 rows, batches 1–17). The questionnaire (psychometric Pre/Post data, batches 7–17) is deliberately not joined. This means there is no join-induced shrinkage or skew of N, and the answer describes the full registry for the cohort. The consensus answer is that Batch 14 has 148 participants in 148 rows, so the one-row-per-participant grain holds. The cohort is 81 FEMALE (54.73%) and 67 MALE (45.27%), and all 148 fall within the two allowed Gender values. Age_At_Workshop is the participant's age at the first (Point-1) workshop. One male participant has the sentinel value 0, which the schema defines as 'unknown', so 147 ages are usable (81 female, 66 male). The cohort is young and tightly clustered. Overall the mean is 22.26 and the median 22. Females have a mean of 22.17 and a median of 22. Males have a mean of 22.36 and a median of 22. All figures are descriptive of a single-arm observational cohort and carry no causal meaning.

Schema Entity / Table Role in Answer Relevance & Meaning
prod_nirman_demographics (Demographics Table) The only table used. Its grain is one row per Participant_Id, so the unique-ID count and the raw row count must agree (148 = 148). It supplies the cohort filter (Workshop_Batch_Number == 14), the gender split, and the age-at-first-workshop distribution. All four columns used sit in the 'usable' zero-missing tier, so no low-coverage column filter changes N. The only data-quality handling needed is the Age_At_Workshop = 0 'unknown' rule. Relevant Columns: Participant_Id, Workshop_Batch_Number, Gender, Age_At_Workshop
prod_nirman_questionnaire (Questionnaire Table) - intentionally not used Holds the Pre/Post psychometric responses (grain: Participant_Id × Workshop_Level × Workshop_Phase, 4,304 rows, 2,177 participants, batches 7–17). The question forbids it. Joining it would turn the one-to-many relationship into repeated rows per participant. It would also restrict the population to participants who completed the survey, so N and the age and gender mix would be affected. Keeping it out is why N = 148 can be compared directly with the registry. Participant_Id would still need a string cast in both tables if a join were ever added. Relevant Columns: Participant_Id, Workshop_Batch_Number, Workshop_Phase, Workshop_Level
Participant_Id (key concept) A numeric-looking key (1001–17176) that must be cast to string and never aggregated. All five runs cast it with String(...).trim(). This is what makes the 148 unique IDs vs 148 raw rows check meaningful. Any duplicate would signal a load or grain problem, and none was found. Relevant Columns: Participant_Id
Age_At_Workshop (sentinel-coded measure) An integer with a documented range of 0–32, where 0 = unknown. It is the age at the first (Point-1) workshop, not the current age. It must be filtered to > 0 before any mean or median. In Batch 14 one MALE participant carries 0. The runs therefore report n_known_age = 147 and n_excluded_unknown_age = 1, split 0 female and 1 male. Relevant Columns: Age_At_Workshop, Current_Age
Domain Business Insights from Schema:
  • Treat the Batch 14 profile as 148 participants: 81 FEMALE (54.73%) and 67 MALE (45.27%). Report percentages against N_total, and always quote the effective N (147 overall, 81 female, 66 male) beside any age statistic.
  • Keep the Age_At_Workshop > 0 filter as a standing rule in all cohort-profile code, and report n_excluded_unknown_age every time. Consider asking the data owners to back-fill the one unknown male age rather than leaving a sentinel in the registry.
  • Use the median (22) as the headline central age and the mean (22.26) as supporting evidence. The trimmed-mean check shows only a slight right tail, so neither is distorted. The roughly 0.2-year male–female difference is too small to be meaningful at these sample sizes.
  • Compare Batch 14 with neighbouring batches, using the same filters and exact column names, before drawing conclusions about intake trends. Batch 14 alone cannot show whether the cohort is typical.
  • If the analysis is extended to questionnaire outcomes, cast Participant_Id to string in both tables and recompute the effective N after the join. Restrict Pre/Post comparisons to Workshop_Level 0.1 and keep Post-phase variables out of any long-term outcome model.
  • Keep wording descriptive. Say 'the cohort has a median entry age of 22', not that the workshop attracts or produces a certain kind of participant.
