4 4. Answer Contextualized by Schema & Domain Model
How the Project Schema Explains & Validates This Answer:

The question asks how satisfied female Medical-stream NIRMAN participants say they are with their lives right after a workshop, and how that varies across the Point 1, Point 2 and Point 3 workshops. It also asks how Point 1 Post scores compare with the same women's Pre scores. The cohort is defined from the Demographics table (prod_nirman_demographics: one row per Participant_Id, 2,890 rows, batches 1-17) with Gender == 'FEMALE' and Educational_Stream_Category == 'Medical'. That rollup excludes Pharmacy and must not be mixed with Educational_Stream = 'Medical / Public Health'. The outcome comes from the Questionnaire table (prod_nirman_questionnaire: grain Participant_Id x Workshop_Level x Workshop_Phase, 4,304 rows, batches 7-17). The outcome is Metric_Life_Satisfaction_Global, the agreement-scale item 'All things considered I am satisfied with my life' (1 = strongly disagree, 5 = strongly agree; agree >= 4, disagree <= 2). The consensus funnel follows the schema's one-to-many join. 749 cohort women in Demographics became 1,180 questionnaire rows from 627 women. The other 122 women have no questionnaire rows, consistent with the batch 1-6 gap and non-participation. Of the 1,180 rows, 561 are Post rows (368 / 150 / 43 at Levels 0.1 / 0.2 / 0.3) from 472 unique women. The 89 extra rows (561 - 472) come from women who completed Post surveys at more than one level. The schema's cleaning rule (0 = not answered, > 5 invalid) removed 16 Post rows, all zeros, leaving 545 valid Post rows from 456 women. Post satisfaction is moderately high: mean 3.82, median 4, SD 1.04, 65.69% satisfied and 11.19% dissatisfied. In the Point 1 paired view (N = 352) the mean moves from 2.86 to 3.84 (+0.98). In this single-arm observational program data, that is an association and an observed change, not a demonstrated workshop effect.

Schema Entity / Table Role in Answer Relevance & Meaning
prod_nirman_demographics (Demographics) Defines the cohort. It holds objective facts at one row per participant. Gender and Educational_Stream_Category are 'usable' columns with no missing values, so the 749-woman cohort is a complete and reliable filter. The filter is applied before the join, so the cohort size is not distorted by questionnaire coverage. The Medical definition is the rollup 'Medical' (Pharmacy excluded), not Educational_Stream 'Medical / Public Health'. Demographics covers batches 1-17, which is wider than the questionnaire. Relevant Columns: Participant_Id, Gender, Educational_Stream_Category, Workshop_Batch_Number
prod_nirman_questionnaire (Questionnaire) Supplies the outcome and the Pre/Post structure. Each row is one participant's response at one workshop level and phase. Metric_Life_Satisfaction_Global is in the wellbeing_self theme and is a headline column. The table is 'zero-missing', but the schema defines 0 as 'not answered' and values above 5 as out of range for this item, so cleaning is still required. In this cohort all Pre rows sit at Level 0.1 (stated in Run 3's narrative; by subtraction 1,180 - 561 = 619 Pre rows). Post rows exist at 0.1, 0.2 and 0.3, so Pre/Post pairing is possible only at Point 1. Relevant Columns: Participant_Id, Workshop_Phase, Workshop_Level, Metric_Life_Satisfaction_Global, Workshop_Batch_Number, Workshop_Name
Join: Participant_Id (Demographics 1 -> Questionnaire many) The string-cast key join (one-to-many, inner) shrinks and skews N. It produced 1,180 rows from 749 women, covering 627 women. A participant can have a Pre row and several Post rows (one per level), so row counts, participant counts and paired counts are different units. This is why the 561 Post rows, 472 unique Post participants and 545 valid rows must be kept distinct. Participant_Name, Workshop_Name and Workshop_Batch_Number exist in both tables and must be dropped or suffixed to avoid collisions. Workshop_Name 'F' must be read as a string. Relevant Columns: Participant_Id, Participant_Name (excluded PII), Workshop_Name, Workshop_Batch_Number
Derived Pre/Post paired frame (Level 0.1 only) The schema's pre_post_pairing recipe: split by Workshop_Phase, suffix _pre/_post, inner-merge on Participant_Id within the same Workshop_Level, then delta = post - pre. Pairing needs a valid score in both phases, so 352 pairs result. That is one fewer than the 353 valid Level 0.1 Post rows, a gap the runs attribute (presumably) to one Post respondent without a valid Pre score; the dossier does not verify this. It is also far fewer than the roughly 600 valid Pre rows, which implies substantial Pre-only attrition. Relevant Columns: Metric_Life_Satisfaction_Global_pre, Metric_Life_Satisfaction_Global_post, Metric_Life_Satisfaction_Global_delta, Workshop_Level
Workshop_Level (0.1 / 0.2 / 0.3) concept Numeric levels map to Point 1, Point 2 and Point 3 workshops. Points 2 and 3 are later-stage, invitation-gated workshops. In Demographics the same follow-up appears as Point_2/3_Workshop_Invited/Attended, so the Level 0.2 and 0.3 groups are self-selected survivors, not random subsets. Compare levels with parseFloat, not as text. Relevant Columns: Workshop_Level, Point_2_Workshop_Invited, Point_2_Workshop_Attended, Point_3_Workshop_Invited, Point_3_Workshop_Attended, Workshops_Attended_Count
Domain Business Insights from Schema:
  • Report the funnel in the order 749 -> 627 -> 561 Post rows -> 472 unique Post women -> 545 valid rows (456 women) -> 352 pairs, and always label the unit (women vs rows) for each number.
  • Present the primary result as the median (4) with the satisfied / dissatisfied split (65.69% / 11.19%) and the full 1-5 distribution, with the mean as a secondary figure. Treat the trimmed-mean and bootstrap outputs as sensitivity checks only.
  • Quantify the Pre-only attrition at Level 0.1. Compare the Pre scores of women with and without a valid Post (the roughly 250 unmatched Pre rows) so the 2.86 -> 3.84 change is not read as representative of all Point 1 attendees.
  • Use Demographics Point_2/3_Workshop_Invited/Attended and Workshops_Attended_Count to examine who reaches Levels 0.2 and 0.3, and stratify or adjust by Workshop_Batch_Number. Comparing Post means across levels should be treated as descriptive only.
  • For the 89 women with Post rows at several levels, run a within-person level-to-level analysis, or cluster by Participant_Id when computing intervals, so repeated rows are not treated as independent.
  • Investigate the zero-coded non-responses (16 Post, 17 Pre) as a data-capture issue. Check whether they cluster by batch or workshop name, and keep the schema rule (0 -> NaN, then drop) with the dropped counts reported.
  • Keep the single Medical definition (Educational_Stream_Category == 'Medical') in the documentation. For sensitivity, run Educational_Stream == 'Medical / Public Health' separately and never combine the two.
  • Word all conclusions as 'associated with' or 'observed change', with the N for every figure, and never state that the workshop improved life satisfaction.
