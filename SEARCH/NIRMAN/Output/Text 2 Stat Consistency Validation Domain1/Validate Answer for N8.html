5-Run Domain Explanations (Schema Context)

Run #1: Direct Danfo.js Filter, Group-By & Parametric Mean/Median Aggregation

This is the baseline and follows the schema's own guidance most literally. It casts Participant_Id to string, parses Workshop_Batch_Number as an integer, and filters to Batch 14. It then counts unique IDs, groups by Gender, and computes the mean and median of Age_At_Workshop > 0. It yields 148 IDs in 148 rows, FEMALE 81 and MALE 67, and age results of 22.26/22 overall, 22.17/22 female and 22.36/22 male. Because Gender and Age_At_Workshop are both zero-missing 'usable' columns, the only exclusion is the single 0-coded male age. Hence overall exclusions (1) = 0 + 1 and known-age counts (147) = 81 + 66. The null/non-numeric diagnostic is 0 because the registry has no gaps in this column. Every other run is judged against this one.

Run #2: Frequency-Table & Cumulative-Distribution Order-Statistic Estimation (with IQR diagnostics)

This run rebuilds the mean as Σ(age × freq)/n and finds the median by scanning cumulative frequencies. It gives the same numbers because ages are integers (documented range 0–32) with heavy clustering, so a frequency table loses no information. The narrative shows ages of 18–29 with an IQR of 20–24 and a mode of 21 overall (28 participants). The median of 22 sits just above the mode because ages are tightly bunched around 21–22, which is typical of an undergraduate/early-graduate intake (Education_Status is Student or Graduate). Females have a mode of 20 and a slightly wider IQR (4 vs 3), so they skew slightly younger at entry. The quartiles are supplementary and do not alter the official mean and median.

Run #3: Stratified Weighted Decomposition & Recomposition

This run computes the FEMALE and MALE strata first and then recomposes the overall figures from them. The age sums are 1,796 for females (81 known) and 1,476 for males (66 known). These give means of 22.17 and 22.36, and the pooled mean is (1,796 + 1,476)/147 = 22.26. The recomposition difference is exactly 0 because the schema allows only FEMALE and MALE in Gender and the OTHER/NULL stratum is empty. The counts recompose too: 81 + 67 = 148, 81 + 66 = 147 known ages, and 0 + 1 = 1 exclusion. The median cannot be recomposed from strata, so it is taken from the pooled sorted array. This run confirms there are no hidden gender categories, no double counting and no misassigned unknown-age rows.

Run #4: Set-Based Partition Reconciliation Audit (with 5% Trimmed-Mean Sensitivity)

This run uses plain JavaScript Sets with no Danfo.js aggregation. It proves that the gender partition (female, male, other) and the age partition (known, zero, invalid) are disjoint and exhaustive over the 148 IDs. It treats null and undefined ages as invalid before coercion, because Number(null) is 0 and would otherwise masquerade as the 'unknown' sentinel. In this data there are no nulls, so the single 0 is a genuine sentinel and belongs to a male participant. The 5% trimmed means are about 0.1 lower (22.16 overall, 22.07 female, 22.27 male). This shows only a mild right tail of older entrants (the maximum is 29 against a mode of 21 and median of 22) and no outlier-driven distortion. Since the ages are integers clustered at 21–22 and the trimmed mean is only a sensitivity check, it does not replace the official mean.

Run #5: Rank-Order Position & Cumulative Share Analysis

This run derives the median as the value at rank (n+1)/2 (or the average of the two middle ranks) and the mean as the final cumulative sum divided by n. It also builds a gender share table (FEMALE rank 1 at 54.73%, cumulative 100.00%). The two middle ranks fall inside the age-22 band for every group. Rank 74 of 147 overall and rank 41 of 81 for females are single middle values, and ranks 33 and 34 of 66 for males are both age 22. That is why every median is 22 with no half-year interpolation. The percentile rank of 22 is about 56% and the share of participants aged 22 or younger is about 65% (65.31% overall). The gap between the two figures implies that roughly 27 participants share age 22 itself, which confirms the dense central band. Because the shares were accumulated unrounded, the cumulative gender share reaches 100 exactly.

Domain Nuances & Constraints

1) Age_At_Workshop is age at the first (Point-1) workshop and is not Current_Age. Batch 14 ages describe entry-time age and should not be read as present-day age. Both columns use 0 = unknown, and in this batch only Age_At_Workshop has been checked. 2) The age result is a mean of integers. Medians of 22.00 reflect integer ages, and even-n groups (males, n = 66) average two middle values that happen to both equal 22. 3) Zero is a sentinel, not a low age. Treating it as an age would pull the male mean down by roughly 0.3 years (1,476/67 ≈ 22.03 vs 22.36) and would change the overall mean to about 22.22. The schema's 'zero_age' value trap exists for exactly this reason. 4) Gender in the schema is only FEMALE or MALE with no missing values, so 'flag any other' returns an empty list. This reflects the registry's coding scheme, not a verified statement about participants' gender identity. 5) Gender percentages use N_total (148) as the denominator. The male age group has n = 66 while the male participant count is 67, so group-level statistics must always quote their own effective n. 6) Batch 14 sits in the more recent portion of the 1–17 range, where 17 is the most recent. Cohort-level outcomes such as Current_Status_Of_Work are right-censored for recent batches, although this question does not use them. 7) The Demographics table covers batches 1–17 while the questionnaire covers only 7–17. Batch 14 exists in both, but the questionnaire may hold fewer than 148 Batch 14 participants, so any later join would change N. 8) Workshop_Batch_Number is the cohort id. It is not Workshop_Name (A–H), which is a low-coverage column naming the workshop instance within a batch and which also needs string loading because 'F' parses as boolean. The question never uses Workshop_Name, so that trap does not apply. 9) This is single-arm observational data, so the results are descriptive and make no causal claim about the workshop. 10) The ONE SHOT EXAMPLE in the context document uses the spelling 'Participant_ID' and an undefined variable. The authoritative column name is Participant_Id, and the runs correctly used that spelling.

Domain Expert Recommendations
  • Treat the Batch 14 profile as 148 participants: 81 FEMALE (54.73%) and 67 MALE (45.27%). Report percentages against N_total, and always quote the effective N (147 overall, 81 female, 66 male) beside any age statistic.
  • Keep the Age_At_Workshop > 0 filter as a standing rule in all cohort-profile code, and report n_excluded_unknown_age every time. Consider asking the data owners to back-fill the one unknown male age rather than leaving a sentinel in the registry.
  • Use the median (22) as the headline central age and the mean (22.26) as supporting evidence. The trimmed-mean check shows only a slight right tail, so neither is distorted. The roughly 0.2-year male–female difference is too small to be meaningful at these sample sizes.
  • Compare Batch 14 with neighbouring batches, using the same filters and exact column names, before drawing conclusions about intake trends. Batch 14 alone cannot show whether the cohort is typical.
  • If the analysis is extended to questionnaire outcomes, cast Participant_Id to string in both tables and recompute the effective N after the join. Restrict Pre/Post comparisons to Workshop_Level 0.1 and keep Post-phase variables out of any long-term outcome model.
  • Keep wording descriptive. Say 'the cohort has a median entry age of 22', not that the workshop attracts or produces a certain kind of participant.

Method 2: Frequency table and cumulative distribution

Idea: never average the raw column directly. Build {age: freq}, get the mean as Σ(age×freq)/N, and find the median by scanning cumulative frequency to the median position(s).

sql
WITH freq AS (                                   -- frequency table per group
    SELECT grp, age, COUNT(*) AS freq
    FROM   age_groups
    WHERE  age > 0
    GROUP  BY grp, age
),
cum AS (                                         -- cumulative frequency + group N
    SELECT
        grp, age, freq,
        SUM(freq) OVER (PARTITION BY grp ORDER BY age) AS cum_freq,
        SUM(freq) OVER (PARTITION BY grp)              AS n
    FROM freq
),
median_calc AS (                                 -- age(s) at position (n+1)/2
    SELECT grp, AVG(age) AS median_age
    FROM   cum
    WHERE  (cum_freq - freq) <  FLOOR((n + 1) / 2.0) AND FLOOR((n + 1) / 2.0) <= cum_freq
        OR (cum_freq - freq) <  CEIL ((n + 1) / 2.0) AND CEIL ((n + 1) / 2.0) <= cum_freq
    GROUP  BY grp
),
mean_calc AS (                                   -- Σ(age × freq) / Σ(freq)
    SELECT grp,
           SUM(age * freq)               AS sum_age,
           SUM(freq)                     AS n_known_age,
           ROUND(SUM(age * freq) / SUM(freq), 2) AS mean_age
    FROM   freq
    GROUP  BY grp
),
excl AS (                                        -- exclusion buckets
    SELECT grp,
           COUNT(*) FILTER (WHERE age = 0)       AS n_excluded_unknown_age,
           COUNT(*) FILTER (WHERE age IS NULL)   AS n_excluded_null_or_non_numeric
    FROM   age_groups
    GROUP  BY grp
)
SELECT
    m.grp,
    m.mean_age                                   AS mean_age_at_workshop,
    ROUND(md.median_age, 2)                      AS median_age_at_workshop,
    m.n_known_age,
    e.n_excluded_unknown_age,
    e.n_excluded_null_or_non_numeric
FROM mean_calc m
JOIN median_calc md USING (grp)
JOIN excl        e  USING (grp)
ORDER BY CASE m.grp WHEN 'OVERALL' THEN 0 WHEN 'FEMALE' THEN 1 ELSE 2 END;
