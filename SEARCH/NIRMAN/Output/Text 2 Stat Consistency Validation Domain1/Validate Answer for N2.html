5-Run Domain Explanations (Schema Context)

Run #1: Direct Set/Map Parametric Baseline (Mean Aggregation)

This run is the reference implementation of the question, using plain Sets and Maps with arithmetic means. The coverage Both = 52 with zero Pre-only, Post-only or Neither follows from every Batch-14 female Medical participant having a Point-1 Pre and Post row. The one-row-per-(participant, level, phase) grain explains the zero duplicates. The single Pre 0 is the 'not answered' rule, which gives valid N of 51 Pre and 52 Post. The unpaired Post mean (3.96) differs from the paired Post mean (3.94) because the participant with the invalid Pre score is dropped from the pairs, and that participant's Post score was 5. The arithmetic reproduces the reported figures: Pre sum ≈ 154 over 51, Post sum 206 over 52, and 201 over 51 when paired, which gives a mean delta of 47/51 = 0.92. The Wilcoxon result (W+ 657 + W− 84 = 741 = 38·39/2) uses only the 38 participants whose score changed, because the 13 'same' pairs are excluded as zero deltas.

Run #2: Robust Non-Parametric Distribution (Median, IQR, Sign Test, Hodges-Lehmann)

The schema marks life satisfaction as a bounded 1–5 agreement (ordinal) item, so rank-based statistics are appropriate. The medians (3 → 4), the modes (Pre 2, Post 4) and the delta IQR of 0 to +2 show that the typical participant gained about one scale point, many stayed put and a few fell. The exact sign test is 33 improved of 38 who changed, so p < 0.001. The Hodges-Lehmann shift of +1 matches the median delta. The matched-pairs rank-biserial r = (W+ − W−)/(W+ + W−) = 573/741 ≈ 0.77 is a large effect. This run explains why the p-values print as 0: they are very small and are shown after 2-decimal rounding. The domain reading is a broad upward movement in the cohort, not a result driven by a few extreme respondents.

Run #3: Danfo.js DataFrame Inner-Merge with Frequency-Weighted Mean Reconciliation

This run follows the schema's own pre_post_pairing recipe: split by Workshop_Phase, suffix _pre/_post and inner-merge on string Participant_Id within Workshop_Level 0.1. The merge returned 51 rows, equal to the native Map join, because only 51 participants have valid scores in both phases. The 52nd participant has an invalid Pre score, so the row is absent from the pairs. The weighted means from the 1–5 frequency table equal the direct means, and (f4 + f5)/N equals the agree%. This confirms that the bucket and frequency logic (valid = integer 1–5) matches the means and the agree% (>= 4) reported in the other runs. The 'tolerance prints as 0' note is a rounding artefact of the 2-decimal rule applied to 1e-9, not a data property.

Run #4: Outlier-Trimmed & De-duplication Sensitivity Analysis

Two sensitivity checks matter in the NIRMAN context. The first is the de-duplication rule. Because the grain allows one row per (participant, level, phase), keep-first, keep-last and single-row-only give identical answers, with a difference of 0 and an unchanged sign. This confirms the data structure, and it does not show robustness to real duplicates, since none exist. The second is trimming. With 51 paired deltas, 5% trimming removes 2 values from each end (floor(0.05 × 51) = 2). The trimmed mean of 0.96 is slightly above the 0.92 mean. This is consistent with the lower tail (declines of up to −2) being a little heavier than the upper tail once the two extremes are trimmed, so extreme respondents are not inflating the gain. One correction: the question text names Metric_Life_Satisfaction_Global explicitly in part (c), so the run's 'assumed, not specified' flag was unnecessary. It does not change any number.

Run #5: Rank-Order Cumulative Distribution, Transition Matrix & Bootstrap CI

This run shows where participants moved on the 1–5 scale. The 5×5 transition matrix has a diagonal of 13 (same), an upper triangle of 33 (improved) and a lower triangle of 5 (declined), so the improved/same/declined counts are internally consistent. Most movement was +1 (16 people) or +2 (13), with 4 at +3, and no decline exceeded 2 points. The bottom-2-box share (scores 1–2) fell from 41.18% to 3.85%, and the paired top-2-box share rose by 31.37 percentage points (37.25% → 68.63%). Much of the shift is low scores moving into the middle and agree bands. The seeded bootstrap 95% CI for mean delta (0.61–1.24) excludes zero. The effect size |r| = 0.69 is z/√n (4.25/√38), which differs from the 0.77 matched-pairs rank-biserial in Run 2. These are two different effect-size definitions of the same signal and do not conflict. The negative z sign is a convention about which rank sum is used as the test statistic.

1) Design: the data is single-arm observational. There is no control group, so the result is association and change only. Method 4: Trimmed means and de-duplication sensitivity

This is fully expressible in SQL.

(i) 5% trimmed means: Pre, Post and paired deltas

sql
WITH series AS (
    SELECT 'pre_valid'  AS series, score AS v FROM v_dedup WHERE phase='Pre'  AND bucket='5_valid'
    UNION ALL
    SELECT 'post_valid',           score      FROM v_dedup WHERE phase='Post' AND bucket='5_valid'
    UNION ALL
    SELECT 'paired_delta',         delta      FROM v_paired
),
ranked AS (
    SELECT series, v,
           ROW_NUMBER() OVER (PARTITION BY series ORDER BY v) AS rn,
           COUNT(*)     OVER (PARTITION BY series)            AS n
    FROM series
)
SELECT  series, MAX(n) AS n,
        FLOOR(0.05 * MAX(n))                   AS k_trimmed_per_end,
        ROUND(AVG(v), 2)                       AS trimmed_mean,
        CASE WHEN FLOOR(0.05 * MAX(n)) = 0 THEN 'no trimming occurred' ELSE 'trimmed' END AS note
FROM    ranked
WHERE   rn >  FLOOR(0.05 * n)

(ii)–(iv) Keep-first vs keep-last vs single-row-only, with robustness vs primary

sql
WITH single_ids AS (       -- exactly one raw row in BOTH phases
    SELECT participant_id
    FROM v_q_rows
    GROUP BY participant_id
    HAVING SUM(CASE WHEN phase = 'Pre'  THEN 1 ELSE 0 END) = 1

      FROM v_q_rows WHERE rn_last = 1 AND bucket = '5_valid'
    UNION ALL
    SELECT 'single_row_only', participant_id, phase, score

ORDER BY variant;
